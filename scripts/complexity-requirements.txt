# Pinned inputs for the complexity gate CI job (see ci/gitlab/ and ci/github/).
#
# Version-and-hash pinned, not a bare `pip install lizard`. That job runs on
# merge/pull request pipelines — including from forks — and pip executes
# packaging code at install time, so an unpinned resolve is arbitrary
# third-party code running in a job that carries a CI token. Pin every tool a
# gate runs on, for the same reason a scanner image is digest-pinned: a tool
# release must not silently change what blocks a merge. This is that bar for a
# pip install.
#
# --require-hashes is what makes the pin real: without it a matching version
# from a different artifact still installs. It also forces a complete graph,
# which is why lizard's two transitive dependencies are pinned here too rather
# than left implicit.
#
# NOT --no-deps: lizard imports pygments at analysis time and reports the failure
# as "Cannot find the lizard_languages module", which reads like a broken install
# rather than a missing dependency. Verified: --no-deps makes the reporter exit 2.
#
# Both the wheel and the sdist hash are listed per package because pip picks
# whichever the runner resolves; a wheel-only pin fails if it falls back to sdist.
#
# To bump: change the version, re-resolve from PyPI, and update the venv the
# PostToolUse hook uses (.claude/hooks/.venv) so local and CI stay on one version.
